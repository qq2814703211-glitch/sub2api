# 0.2.20-GloryCode-0.1.2 发布说明

## V3 渠道监控（admin/channels/monitor 的 V3 tab）

**每组独立探针身份**。此前 V3 只有一条全局探针，所有分组共用一个 key 和一个模型集合——但每个分组接的上游和能用的模型本来就不同，一条探针既证明不了各组的真实可用性，也不该拿同一个 key 去测所有分组。现在 `ChannelMonitorV3Group` 各自带 `Probe`，每组可配自己的密钥、服务商、主模型与附加模型、探测间隔。

顺带修掉一个连带缺陷：原先全局探针的 key 解不出来时，runner 直接 `return` 跳过整轮，哪怕某个分组自己的 key 是好的。改成逐组解密、逐组判空，缺 key 的那组记 warn 跳过，其余分组照常探测。存量配置升级后行为不变——旧全局探针的值会复制到各组，并带 `probe_inherited` 标记。

**缓存率均值窗口可选分钟/天**。原来只有 `cache_average_window_days`（1–90 天，带 CHECK 约束）。现在拆成 value + unit 两个字段，分钟和天都能选。

路径按窗口大小选择：窗口 ≥ 1 天走 `usage_group_daily` 日汇总表（0.1.1 引入，生产实测 19,714ms → 0.3ms，不能被破坏）；窗口 < 1 天时汇总表的 `day DATE` 粒度表达不了，改直扫 `usage_logs`，窗口小所以扫描范围也小。

**已删除的分组不再冒充正常候选**。后端候选查询本来就有 `deleted_at IS NULL AND status = 'active'`，没有泄漏。问题在前端：已配置但已被删除的分组仍要显示（否则配置里卡着删不掉），但它和正常分组长得一样、还默认被勾选。现在这类行标红、隐藏开关（不可再启用）、显示「该分组已删除」带原 id，可移除。

## 用户管理 admin/users

**列表并发数与详情请求数统一口径**。此前两处读的是完全不同的两个数据源：列表读 Redis 槽位集合（`concurrency:apikey:<id>`）的占用数，详情读在途请求登记（`usage:inflight:<uid>`）的条数。同一个用户列表显示 39、点开却是 91，因为根本不是一个东西。现在列表也读在途请求数，两处对同一用户返回同一个值。

同时清掉一处双写：`fillCurrentConcurrency` 取完并发数后，`FillAPIKeyQueueStats` 又在同一循环里用槽位值覆盖了一次，后写的赢。

**提示气泡空白**。`HelpTooltip` 的 prop 叫 `content`，调用处传的是 `:text=`，传了个不存在的 prop，所以悬停永远空白。i18n 键本身是好的（zh/en 都有）。改 prop 名即可。全仓只有这一处错配。

**按当前并发排序**。原先后端的 `case "concurrency"` 映射到 `users.concurrency`——那是并发**上限**配额，不是实时值。而多数用户上限相同（5 或 10），排出来看着就像按 ID。实时值在 Redis 里，SQL 排不了，改成批量取在途数后应用层排序再分页。

## 生图广场 image-studio

**AI 改写密钥与生图密钥分离，同卡片呈现**。两个密钥在同一张卡片里分别标注「生图密钥」「AI改写密钥」并说明用途；卡片只放两个密钥输入框、说明、校验令牌按钮、详细配置按钮，其余配置收进弹窗。

**协议自适应**。界面上不再有协议选择控件，由程序判定。

**地址写死**。改写接口地址固定为站内 `https://api.example.com`，不再给用户填写。存量 localStorage 里手填的 baseUrl 与 protocol 直接忽略——旧脏值也不会再把改写卡死。
