# models.dev 价格写入覆盖层，但不覆盖手动定价

models.dev 提供一份官方参考价，我们的 `pricing.override_file` 提供一份可热更新的本地价表。把两者接起来做"实时官方价"很自然，但二者的语义不同：models.dev 是**参考价**，我们价表里手工配过的是**结算价**（含倍率、活动、渠道成本）。如果同步来的官方价无条件写进覆盖层并压过手动定价，做一次同步就会把商业定价冲掉。

决定：同步任务自动把 models.dev 的价格写进 `pricing.override_file` 并触发热重载，但只写**我们的价表里还没有手动定价**的模型；任何已手工配置过的模型都不被覆盖。每次写入在 `model_pricing_sync_history` 留一行记录（模型、字段、旧值、新值、来源、生效时间）。

代价：官方调价时，手工配过的模型不会自动跟随。这是有意的 —— 那类模型的价格由运营决定，不由上游目录决定。

## 归属判据：比对值，而不是比对字段名

「这个字段是谁写的」由变更史判定，但**不能只看字段名有没有出现过**。真实顺序通常是同步先写入某个模型、过一段时间运营才手动改价；此时该字段既非零、又出现在变更史里，只比对字段名会把它判成同步所有，下一轮静默覆盖掉运营的手工价。实测确认过这个覆盖真的发生（`9e-06` 被改回 `4e-06`）。

所以仓库返回的是**上次同步写进去的值**（`DISTINCT ON (model, field)` 取最近一行的 `new_value`），判定规则变成：

- 当前值 == 上次同步写入值 → 同步自己的字段，可以跟随官方价更新；
- 当前值 != 上次同步写入值，或字段不在变更史里 → 有人手工改过，整个模型跳过。

单元测试都建立在空变更史上，这类顺序覆盖不到，因此单独加了 `TestModelPricingSync_ManualEditAfterPriorSyncSurvives`：把变更史预置成「同步写过 4e-06」、覆盖层放 9e-06，断言同步后仍是 9e-06。把判据退回旧版时该用例会失败，说明它确实能区分。

## 与真实结算价的关系

`override_file` 没有人工编辑接口，只有同步任务会写它。运营真正手动定价的位置是分组价卡（ChannelModelPricing），而解析顺序是先查价卡、命中就根本不读全局覆盖层。所以「同步不会冲掉商业定价」最终由这条优先级链保证，覆盖层的归属判据是第二道防线。
